# Sound plan: tiers wave orders (2026-09-27)

JS: "triple the sound that just make, make a sound plan to use all new order". Two parts:

1. **3 takes** for the 27 per-family unit cues (9 families x attack / hit / death): `<id>.wav`, `<id>_1.wav`,
   `<id>_2.wav` = 81 files (`assets/audio/unit_sfx_generator.gd`). Takes 1 / 2 re-render the same recipe with another
   pitch (x0.91 / x1.10), length (x1.12 / x0.90), brightness and fresh noise, loudness-matched to take 0 (max 200 ms
   RMS, Audio Lab TAKE_TOL 2 dB). GameAudio picks a take at random, **never the same one twice in a row**
   (`GameAudio.pick_take`), on top of the +-7 % pitch. Frequent new cues get 3 takes too (marked **3x** below).
2. **Every order / action added today has a sound**, generated by `assets/audio/order_sfx_generator.gd` and wired in
   `scripts/audio/game_audio.gd` (`SOUND_PLAN` = this table in code). Everything is hooked from GameAudio through
   signals or public state (polled at 10 Hz): **no gameplay file was edited**.

Who hears it: **own** = only the local player's events (2D, UI voice); **3D** = at the unit, anyone's, only when the
unit is visible (fog) and within 75 m of the camera. Enemy keep / "+" upgrades and enemy helper events stay silent
(no free scouting); an enemy Saboteur's disguise never makes a sound.
